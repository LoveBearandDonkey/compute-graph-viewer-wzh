# 昇腾算子内存可视化工具 —— 场景与功能规划

> 版本：v0.1（规划草案）
> 说明：本文用于对齐工具定位、使用场景与功能边界，作为后续需求拆解与技术选型的输入。文中涉及的具体硬件容量数值仅为占位示例，实际以对应芯片型号的官方规格为准，工具内部必须做成**可配置的芯片描述文件**而非硬编码。

---

## 1. 背景与问题

昇腾 AI Core（达芬奇架构）的算子开发与 GPU 有一个本质差异：**片上内存是显式管理的**。开发者需要自己把数据从 Global Memory 搬到 L1 / Unified Buffer / L0A/L0B/L0C，自己安排复用、对齐、double buffer 和同步。这带来几类高频痛点：

| 痛点 | 现状表现 |
| --- | --- |
| Buffer 超限 | 编译期报 "buffer size exceeds limit"，只知道超了，不知道**谁**超了、超多少、改哪个 tiling 参数最有效 |
| 利用率低 | UB 只用了 40%，但开发者无从感知，性能被搬运次数拖死 |
| Double buffer 失效 | 以为开了 ping-pong，实际因分配方式或同步位置退化成串行 |
| 复用冲突 / 越界 | 两个 tensor 生命周期重叠却复用了同一块地址，表现为随机精度问题，极难定位 |
| Tiling 决策靠试 | 改一个 tile 大小 → 重编译 → 看报错或跑 profiling，反馈环路长达分钟级 |
| 知识不可传递 | 内存布局只存在于资深开发者的脑子里和注释里，评审、交接、教学成本极高 |

**工具的一句话定位**：把昇腾算子的片上/片外内存分配，从"脑子里的隐式模型"变成**可看、可比、可校验、可进 CI** 的显式视图。

## 2. 前置约定：内存层次抽象

工具需要建模的存储层级（按型号配置容量、bank 数、对齐粒度、带宽）：

| 层级 | 归属 | 典型用途 | 关注点 |
| --- | --- | --- | --- |
| Global Memory (HBM/DDR) | 片外 | 算子输入/输出、workspace | 峰值占用、workspace 规模、算子间复用、碎片 |
| L2 Cache | 片上共享 | 跨核数据复用 | 命中率、多核争用（可选，二期） |
| L1 Buffer | 片上/核内 | Cube 输入暂存、大块中转 | 容量、分配布局 |
| L0A / L0B / L0C | 片上/Cube 专用 | 左矩阵 / 右矩阵 / 累加输出 | 容量、分形（fractal）对齐 |
| Unified Buffer (UB) | 片上/Vector 专用 | Vector 计算输入输出 | **最核心视图**：容量、对齐、bank 冲突、double buffer |
| Scalar Buffer / ICache | 片上 | 标量与指令 | 一般只看是否溢出 |

并行地建模**执行流水单元**，因为内存事件必须挂在流水上才有意义：
`MTE2(GM→片上)`、`MTE1(L1→L0)`、`MTE3(片上→GM)`、`Cube`、`Vector`、`Scalar`、`FixPipe`。

## 3. 目标用户与使用场景

### 场景 1：算子首次开发期的 buffer 规划（核心场景）
- **角色**：Ascend C 
- **触发**：新写一个算子，需要决定 tiling 切分与各 tensor 的 buffer 归属
- **痛点**：容量约束在脑子里算，靠画草图和 Excel 估算
- **工具介入**：解析源码中的 `InitBuffer` / `AllocTensor` / `TQue` 声明 + TilingData，给出**静态内存布局图**与水位线，实时提示"UB 已占 231KB / 256KB，剩余 25KB"
- **成功判据**：不用编译就能知道会不会超限；从"改-编-看报错"缩短到秒级反馈

### 场景 2：编译期 buffer 超限的快速定位
- **角色**：算子开发者
- **触发**：编译报错 buffer 超限
- **工具介入**：把超限归因到具体 tensor / 队列 / 源码行，并给出**敏感度分析**——"把 `tileNum` 从 8 降到 6 可释放 48KB"、"`tmpBuf` 与 `castBuf` 生命周期不重叠，可复用节省 32KB"
- **成功判据**：定位时间从小时级到分钟级

### 场景 3：性能调优中的搬运/计算重叠分析
- **角色**：性能优化工程师
- **触发**：算子达不到目标 cycle 数，怀疑瓶颈在数据搬运
- **工具介入**：把内存事件与流水时序**叠在同一时间轴**上（MTE2/MTE3 通道 + UB 占用曲线），直观暴露：double buffer 是否真的重叠、是否存在同步等待空洞、搬运是否成为关键路径
- **成功判据**：能指着图说出"这段 Vector 在等 MTE2，因为 buffer 只开了单份"

### 场景 4：Tiling 策略对比与择优
- **角色**：算子开发者 / 自动 tiling 调优流程
- **触发**：多个 tiling 候选需要横向比较
- **工具介入**：并排/差分展示 N 组 tiling 的峰值占用、利用率、搬运次数、尾块（tail block）浪费；支持批量扫描后出对比表
- **成功判据**：tiling 选择从经验判断变成数据判断

### 场景 5：内存越界与复用冲突的正确性排查
- **角色**：算子开发者 / 测试
- **触发**：精度不稳定、偶发错误结果
- **工具介入**：生命周期甘特图上标红**地址区间重叠 且 生命周期重叠**的 tensor 对；标出越界读写（访问范围超出声明区间）与读未写（未初始化）区域
- **成功判据**：把"随机精度问题"转成一条明确的冲突记录

### 场景 6：融合算子 / 大算子的 workspace 与 GM 规划
- **角色**：融合算子开发者、图优化工程师
- **触发**：多个子计算拼成一个大算子，workspace 越滚越大
- **工具介入**：GM 侧的 tensor 生命周期与复用视图，给出理论最小 workspace 与当前值的差距，提示可复用组合
- **成功判据**：workspace 显著下降，且改动有据可依

## 4. 关键功能特性

### 4.1 数据采集层（多来源、可插拔）

| 来源 | 采集内容 | 依赖 | 阶段 |
| --- | --- | --- | --- |
| **静态源码解析** | `TPipe/TQue/TBuf` 声明、`InitBuffer`、`AllocTensor/FreeTensor`、`DataCopy` 范围 | 源码 + Clang AST 或轻量解析 | MVP |
| **Tiling 数据** | TilingData 结构、block dim、切分参数 | tiling 函数输出 / host 侧打印 | MVP |
| **编译中间产物** | 实际 buffer 分配结果、地址偏移、符号表 | 编译日志 / CCE 中间文件 | MVP+ |
| **Profiling 数据** | 各流水单元耗时、任务时序 | msProf / CANN profiling 输出 | V1 |
| **指令级 trace / 模拟器** | 逐指令的内存访问与同步事件 | 功能/周期模拟器 | V2 |
| **手工插桩打点** | 关键点位的自定义标记 | 提供轻量 API/宏 | V1 |
| **框架侧内存快照** | 模型级 device 内存分配与碎片 | torch_npu / GE 内存接口 | V2（可选扩展） |

**设计要求**：所有采集器统一输出到中间格式（见 §6），前端只认中间格式 → 新增来源不动可视化层。允许**部分数据缺失时降级展示**（只有静态数据也能出布局图）。

### 4.2 统一内存数据模型
- 实体：`Chip Spec` / `Kernel` / `Core(block)` / `MemoryRegion(层级)` / `Buffer(队列或TBuf)` / `Tensor(逻辑张量)` / `Allocation(地址区间+生命周期)` / `Event(搬运/计算/同步)`
- 关键属性：地址偏移、大小、对齐要求、数据类型与 shape、所属流水、生命周期（起止时间或指令序号）、来源（源码文件:行）
- 支持**逻辑视图与物理视图分离**：同一 tensor 在不同层级的多份副本可关联追踪

### 4.3 可视化视图（核心竞争力）

1. **内存布局图（Layout Map）**
   地址空间为纵/横轴的条带图，按层级分栏；色块 = 分配区间，空隙 = 碎片；hover 显示 tensor 名、大小、对齐、源码位置
2. **生命周期甘特图（Lifetime Gantt）**
   Y 轴 = tensor/buffer，X 轴 = 时间或指令序；用于看复用机会与冲突；重叠冲突高亮标红
3. **占用水位曲线（Watermark）**
   每层内存的 used/capacity 随时间变化，标注峰值点及其构成（top-N 贡献 tensor）
4. **流水 × 内存联合时序视图**
   多泳道（MTE1/2/3、Cube、Vector、Scalar）+ 内存事件与水位叠加；这是判断 double buffer 与瓶颈的主视图
5. **利用率 / 碎片热力图**
   按 tiling 参数或按核（block）二维展开，快速找到最差的核或最差的参数组合
6. **Tiling 对比 / Diff 视图**
   两个或多个配置并排，指标表 + 布局差异高亮（新增/消失/变大的分配）
7. **层级下钻**
   模型 → 算子 → 核 → 层级 → buffer → tensor，逐级钻取，面包屑返回
8. **源码联动**
   点击色块跳转源码行；反向从源码行高亮对应内存区域

### 4.4 分析与诊断规则引擎
内置规则库，输出「问题 + 位置 + 量化影响 + 建议动作」四元组：

- **容量类**：超限；接近阈值（如 >90%）；某层严重闲置（如 UB <50%）
- **对齐类**：未满足对齐粒度导致 padding 浪费；非对齐搬运导致低效
- **复用类**：生命周期不重叠但未复用（可节省 X KB）；地址重叠且生命周期重叠（正确性风险）
- **流水类**：double buffer 未生效；搬运未与计算重叠；同步等待空洞占比过高
- **Bank 冲突类**：并发访问落在同一 bank 的疑似模式（依赖型号规格）
- **尾块类**：tail block 造成的算力/带宽浪费比例
- **回归类**：与基线对比的指标劣化

规则应可**开关、可配阈值、可自定义扩展**（YAML/插件形式），避免噪声淹没真问题。

### 4.5 交互能力
- 时间轴 scrub / 缩放 / 框选区间聚焦
- 按 tensor、queue、流水单元、核号过滤与搜索
- 标注与批注，可随报告一起导出（服务评审场景）
- 快照对比（A/B 两次采集）
- 键盘导航与大数据量下的虚拟化渲染

### 4.6 集成与输出
- **CLI**：`采集 → 分析 → 报告/退出码`，适配 CI；支持 `--baseline` 与 `--fail-on`
- **单文件 HTML 报告**：零依赖、可邮件/PR 附件传递
- **开放中间格式**：JSON schema 公开，允许第三方生成或消费
- **Trace 兼容导出**：导出 Chrome Trace / Perfetto 格式，复用成熟时序查看器
- **IDE / MindStudio 插件（可选）**：编辑器内旁栏实时显示水位
- **Python API**：便于自动 tiling 搜索脚本调用，把工具当成评估函数

## 5. 非功能需求
- **离线可用**：不依赖外网与上板环境（静态路径）
- **规模**：单算子 trace 万级事件流畅；模型级十万级事件可分页/采样
- **多型号**：芯片规格以配置文件描述（容量/bank/对齐/流水单元集合），新增型号不改代码
- **数据安全**：源码与 shape 信息可能敏感，支持本地运行与字段脱敏导出
- **可解释**：任何结论都能溯源到原始数据项，不做黑盒推断
- **鲁棒性**：输入不完整、版本不匹配时明确降级提示，而非崩溃或静默错误

## 7. 技术方案候选

| 模块 | 候选 | 取舍 |
| --- | --- | --- |
| 解析器 | Clang/LibTooling AST vs 正则+轻量文法 | AST 准确但重；建议先轻量解析覆盖主流写法，再演进 |
| 分析核心 | Python | 生态好、与调优脚本天然集成 |
| 可视化 | Web（D3/Canvas/WebGL）单文件产物 | 跨平台、易分发；大数据量走 Canvas 而非 SVG |
| 时序视图 | 自研 vs 导出 Perfetto | 一期直接复用 Perfetto 降低成本，二期自研做深度联动 |
| 分发形态 | pip 包 + CLI + HTML 报告 | 最低摩擦；IDE 插件后置 |

## 10. 成功度量

| 维度 | 指标 |
| --- | --- |
| 效率 | buffer 超限定位耗时下降比例；tiling 选型迭代轮次下降 |
