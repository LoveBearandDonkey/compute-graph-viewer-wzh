一条乘法只能算 Rank。

01 / Concrete rule counterexamples

人有我优：总量规则之上，
再检查算法真正需要的约束。

下面不是概念示意，而是当前 Demo 已落地的公式。每个案例都展示一个“常见规则能通过、细分算法会失败”或“同一配置因框架口径不同而结论不同”的反例。

R01 · MINDSPEED ULYSSES CP已实现

Head 能被 TP 整除，仍不代表 Ulysses 合法

Ulysses 会在 TP 之外继续按 CP 拆分注意力头，因此校验因子不是 TP，而是 TP×CP。

配置输入：heads=24 · TP=4 · CP=4 通用模型-校验：24 % 4 = 0 → 通过 如果用本 MCP-校验：Ulysses 要求 24 % (4×4) = 8 → 拒绝 如果用本 MCP-诊断码：MINDSPEED_ULYSSES_HEADS_DIVISIBLE_BY_TP_CP

优势：从“并行度可乘”深入到“算法切分单元可落地”。

R02 · MINDSPEED RING CP已实现

序列能被 CP 整除，仍可能不满足 Ring

Ring 口径需要序列长度被 2×CP 整除；只查 seq % CP 会漏掉半环切分问题。

配置输入：sequence=4098 · CP=2 通用模型-校验：4098 % 2 = 0 → 通过 如果用本 MCP-校验：Ring 要求 4098 % (2×2) = 2 → 拒绝 如果用本 MCP-诊断码：MINDSPEED_RING_SEQUENCE_DIVISIBLE_BY_2CP

优势：不是把 CP 当一个数字，而是识别 CP 算法。

R03 · DYNAMIC PIPELINE已实现

62 层不能均分 8 个 Stage，但可以合法动态分层

简单规则只会报 62 % 8 != 0。MindSpeed-LLM MCore 动态 PP 允许非均匀分层，但必须同时满足列表长度、层数总和、Profile 与 VPP 互斥关系。

配置输入：layers=62 · PP=8 · VPP=1 通用模型-校验：uniform 要求 62 % 8 = 0 → 拒绝 如果用本 MCP-校验：dynamic [8,8,8,8,8,8,7,7] → 长度=8、总和=62，通过 如果用本 MCP-适用范围：仅 mindspeed-llm-mcore Profile 接受

人无我有式差异：不是更苛刻，而是能表达合法的非均匀解。

R04 · FRAMEWORK PROFILE已实现

同样的 62 层分配，不同框架不能混用表达法

MindSpeed-LLM MCore 使用 num_layer_list；MindFormers offset 使用 VPP×PP 矩阵。当前核心会先校验 Profile，再校验矩阵形状与每个虚拟 Stage 是否为正整数。

配置输入：layers=62 · PP=8 · VPP=1 如果用本 MCP-校验：MCore 接受 [8,8,8,8,8,8,7,7] 如果用本 MCP-校验：MindFormers 接受 offset [[0,0,0,0,0,0,-1,-1]] 如果用本 MCP-校验：跨 Profile 混用 list 与 offset → 拒绝 如果用本 MCP-行为原则：差异显式返回，不静默选择框架口径

优势：把“公式是否正确”提升为“公式对这个框架是否正确”。

R05 · EP DOMAIN SEMANTICS已实现

EP 是否进入 World Size，不能一概而论

当前核心显式建模三种 EP 口径。相同的 DP=2、TP=4、EP=4，在不同域语义下会得到不同合法性和 Rank 公式。

配置输入：DP=2 · TP=4 · EP=4 · EP 口径=split / mf / orthogonal 如果用本 MCP-计算公式：world = DP×PP×TP×CP×(orthogonal ? EP : 1) 如果用本 MCP-校验：split 口径下 DP % EP = 2 % 4 → 不合法 如果用本 MCP-校验：mf 口径下 (DP×TP) % EP = 8 % 4 → 合法 如果用本 MCP-口径说明：orthogonal 时 EP 进入 world；其余两种不进入

人有我优：避免把某个框架的 EP 公式冒充行业统一真理。

R06 · MOE COHERENCE已实现

Rank 乘积正确，也可能是自相矛盾的 Dense / MoE 配置

模型没有路由专家时，EP 必须回到 1、Top-K 必须为 0；有专家时，还要检查专家数能否被 EP 整除、Top-K 是否超过专家总数。

配置输入：routed_experts=0 · EP=4 · top_k=2 通用模型-校验：只核对 world size → 可通过 如果用本 MCP-校验：Dense 语义要求 EP=1 且 top_k=0 → 两项拒绝 如果用本 MCP-校验范围：Expert FFN / TP 仅在专家张量并行开启时检查

优势：检查字段之间的状态一致性，而非孤立检查数值范围。

R07 · HYBRID CP已实现

CP 总度数正确，Hybrid 内部仍可能无法分解

Hybrid CP 不只检查 sequence % CP，还要求 Ulysses degree 能整除 CP、Ring degree 大于 1，并继续联动 Head 与 window。

配置输入：CP=8 · Ulysses degree=3 · TP=2 通用模型-校验：只核对 sequence % 8 = 0 → 可通过 如果用本 MCP-校验：Hybrid CP 要求 8 % 3 = 0 → 拒绝 如果用本 MCP-诊断码：MINDSPEED_HYBRID_CP_DEGREES_FORM_CP

优势：校验算法内部的二维分解，而不是只认一个 CP 总数。

R08 · ASCEND MC2 / COC已实现

两个开关各自合法，组合起来却互斥

Schema 只能证明布尔值格式正确；规则核心会判断 MC2 与 CoC 不能同时启用，并进一步检查它们与 MoE 的兼容关系。

配置输入：use_ascend_mc2=true · use_ascend_coc=true 通用模型-校验：两个字段均为合法 boolean 如果用本 MCP-校验：MindSpeed 中 MC2 ∧ CoC → 拒绝 如果用本 MCP-诊断码：MINDSPEED_MC2_COC_MUTUALLY_EXCLUSIVE

优势：从单字段校验进入昇腾通信特性的组合合法域。

R09 · AMPIPE PREREQUISITES已实现

启用 AMPipe 不是填一个 degree 就够了

核心同时检查 FlashAttention、MoE、EP、deepspeed_moe、序列整除，以及与 MC2、NanoPipe、多个 overlap / recompute 开关的互斥。

配置输入：ampipe_degree=2 · flash_attention=false · EP=1 通用模型-校验：degree ≥ 1 → 通过 如果用本 MCP-校验：缺 FlashAttention 且 EP≤1 → 拒绝 如果用本 MCP-诊断输出：返回两个独立稳定诊断码与关联字段

优势：一次判断完整功能开关簇，而不是等到启动路径逐个断言。

R10 · 2D TP已实现

TP=8 合法，不代表 2D TP 的两个维度合法

启用 2D TP 后，必须满足 TP = tp_x × tp_y，并检查 CP 模式及与 MoE、CoC、AMPipe、NanoPipe、Sequence Parallel、Fused RMSNorm 的支持边界。

配置输入：TP=8 · tp_x=2 · tp_y=2 通用模型-校验：8 是有效 TP 并行度 如果用本 MCP-校验：2D TP 要求 8 = 2×2 → 拒绝 如果用本 MCP-诊断码：MINDSPEED_TP2D_FACTORS_MATCH_TP

优势：把特性维度、并行维度和互斥矩阵放在同一次静态求值中。

R11 · ND MATMUL已实现

TP 乘积合法，也可能无法进入 ND MatMul 路径

ND MatMul 还要检查归一化类型、checkpoint 加载状态，以及 TP 能否分别被 ND1 / ND2 的 dim1 切分。

配置输入：TP=8 · ND1 dim1=3 · normalization=layernorm 通用模型-校验：8 是有效 TP 并行度 如果用本 MCP-校验：ND MatMul 中 8 % 3 != 0 且 LayerNorm 不兼容 如果用本 MCP-诊断输出：返回维度整除与归一化两个独立诊断

优势：不仅知道“开了特性”，还知道它能否进入对应算子路径。

R12 · MOE OVERLAP已实现

Overlap 开关为 true，不代表通信重叠链路完整

AllToAll / AllGather overlap 各自绑定 dispatcher，并共同要求异步 permutation 与 grouped GEMM；TP>1 的 AllToAll 还要求 TP extend EP。

配置输入：alltoall_overlap=true · dispatcher=allgather 如果用本 MCP-校验：dispatcher 不匹配 → 拒绝 如果用本 MCP-校验：async permutation=false · grouped GEMM=false → 再拒绝两项 如果用本 MCP-诊断输出：一次输入同时暴露完整前置条件链

优势：交叉检查 dispatcher、通信、算子和并行域，不做孤立布尔校验。

R13 · MEMORY / RECOMPUTE已实现

三个“省显存”能力同时打开，反而可能互斥

Adaptive Recompute 不能与静态重计算并用；Adaptive Memory Optimization 又与 AMPipe、Adaptive Recompute 和静态重计算分别互斥。

配置输入：adaptive_memory=true · adaptive_recompute=true · recompute=full 通用模型-校验：三个枚举 / boolean 均合法 如果用本 MCP-校验：组合语义同时命中三类互斥关系 如果用本 MCP-定位范围：诊断定位到 features 与 memory 两个配置域

优势：能发现“每个开关都合理、组合却没有合法执行路径”的配置。

R14 · NON-BLOCKING STRATEGY已实现

不推荐，不等于不合法

910B 上 CP=8、序列 32768 时，每个 CP 分片只有 4K tokens，低于 Auto Settings 的 8K 启发式；核心只给降低 CP 的建议，不改变合法性。

配置输入：card=910B · sequence=32768 · CP=8 如果用本 MCP-合法性结果：静态约束全部通过 → valid=true 如果用本 MCP-策略建议：保留 CP 候选 [1,2,4] 如果用本 MCP-建议码：MINDSPEED_CP_SLICE_BELOW_DEVICE_HEURISTIC

优势：把“不能运行”和“可能不优”分成两条输出通道。

02 / Multi-parameter constraint graph

不是把 82 条规则逐个跑一遍，
而是让一份配置穿过多参数约束图。

普通字段检查通常回答“类型对不对、范围对不对、单个整除式是否成立”。MCP 继续检查功能开关的前置条件、互斥簇、算法分解和跨配置域依赖；即使每个字段单独都合法，组合仍可能被拒绝。

“通用模型可能知道”不等于“每次都能完整执行”

通用大模型在提示充分时可能指出其中若干冲突，但结果受上下文和推理稳定性影响。本 MCP 把关系固化为确定性代码：一次求值不会在第一条错误处停止，而是返回完整的 code + fields + formula + sourceRef，修复候选还要重新通过整张规则图。

示例同时设置 AMPipe=2、CP=2/Ulysses、sequence=4100，并打开 MC2、bias、两种 overlap、NanoPipe、bubble/advance/adaptive recompute，却未启用 FlashAttention且使用 megatron_moe。

普通字段检查：boolean / enum / degree 范围全部合法 MCP：闭包涉及 18 个字段，一次返回 14 个冲突 覆盖：前置条件 2 + 互斥簇 8 + CP/序列 2 + MoE/重计算 2 代表码：MINDSPEED_AMPIPE_CP_SEQUENCE_DIVISIBILITY

C02 · 2D TP SUPPORT MATRIX11 字段 → 8 诊断

TP = tp_x×tp_y 只是入口，不是完整检查

示例使用 TP=8、tp_x=2、tp_y=2，同时启用 Adaptive CP、Sequence Parallel、Fused RMSNorm、NanoPipe、CoC，并保留 MoE/EP。

普通检查：TP、X、Y 都是正整数；所有开关都是合法 boolean MCP：11 个字段共同命中 8 个支持边界 同时发现：因子、CP 模式、SP、RMSNorm、NanoPipe、2D TP×CoC/MoE，以及 CoC×MoE 代表码：MINDSPEED_TP2D_FACTORS_MATCH_TP

  2. MINDSPEED_TP2D_INCOMPATIBLE_WITH_SEQUENCE_PARALLEL2D TP 不支持 Sequence Parallel。关联字段：features.tp_2d、parallel.sequence_parallel
  3. MINDSPEED_TP2D_INCOMPATIBLE_WITH_FUSED_RMSNORM2D TP 不支持 Fused RMSNorm。关联字段：features.tp_2d、features.use_fused_rmsnorm
  4. MINDSPEED_TP2D_INCOMPATIBLE_WITH_NANOPIPE2D TP 不支持 NanoPipe。关联字段：features.tp_2d、features.use_nanopipe
  5. MINDSPEED_TP2D_CP_MODE_LIMIT2D TP 当前只支持 Ring 或 Ulysses CP；示例配置为 Adaptive。关联字段：features.tp_2d、parallel.cp_mode
  6. MINDSPEED_TP2D_INCOMPATIBLE_WITH_COC2D TP 不支持 Ascend CoC。关联字段：features.tp_2d、features.use_ascend_coc

优势：检查的是“2D TP 这条算子路径能不能成立”，不只是三个数字是否合法。

C03 · MOE OVERLAP CHAIN8 字段 → 5 诊断

Overlap 不是一个开关，而是一条完整依赖链

示例同时打开 AllToAll/AllGather overlap 和 adaptive recompute activation，dispatcher 选 alltoall_seq，却关闭 async permutation、grouped GEMM 与 TP extend EP。

普通检查：每个开关、dispatcher 枚举都合法 MCP：8 字段联动返回 5 个诊断 链路：overlap → dispatcher → async permutation → grouped GEMM → TP extend EP 代表码：MINDSPEED_MOE_OVERLAP_REQUIRES_GROUPED_GEMM

优势：把功能开关背后的完整执行条件一次性展开，而不是逐次试错。

C04 · HYBRID CP DECOMPOSITION7 字段 → 3 诊断

基础整除全部通过，高级算法仍能发现三处错误

Heads=30、KV Heads=5、TP=2、CP=8、Ulysses degree=2、window=3、sequence=32760：Heads÷TP、Heads÷KV 和 Sequence÷CP 都能通过。

普通检查：30%2=0 · 30%5=0 · 32760%8=0 MCP：30%(2×2)≠0 · Ring degree 4 不能被 window 3 整除 · 32760%(2×8)≠0 涉及 Heads、TP、CP、degree、window、sequence、CP mode 共 7 个字段 返回 3 个独立 Hybrid CP 稳定诊断码

优势：这是普通“Head÷TP、Sequence÷CP”检查明确会漏掉的算法内部关系。

01 · INPUT

用户可提供的输入条件

以下四项是并列输入场景，可以只提供一项，也可以任意组合；左右位置没有配对含义。

有硬约束：Total Rank 只能是 128 → 锁定资源规模，只搜索满足 World、PP/TP/CP/EP 和模型结构的候选。 有硬件约束：只能使用昇腾 910、32 GiB → 结合卡型策略与理论容量门禁，排除明显装不下或不适用的组合。 只有部分偏好：必须保留 EP、优先长序列、不能改模型结构 → 作为 locked_fields 和优化目标进入求解器。 什么都不输入：从目标框架与版本化模型 Profile 出发，生成保守、可解释的默认候选，并明确所有假设。
02 · OUTPUT

MCP 的生成结果与交付门槛

以下两项共同定义一次交付：先生成可解释的候选，再通过全量规则复验；二者是前后关系。

目标输出：统一配置 + YAML / Shell 初始脚手架 + 备选方案 + 每个参数的选择理由。 交付门槛：所有候选必须通过 82 个静态诊断、容量门禁和适用策略复验，再标为“静态可用起点”。
