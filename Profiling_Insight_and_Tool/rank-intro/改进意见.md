### 背景
本文只讨论主流的 TP / PP / DP / EP 组合，暂不考虑 CP、SP 以及其他特殊切分方式。
本文不发射讨论非主流的极端、冷门情况。

### 到处都有激活，真正被切分的一个激活单元有多大？

首先，因为采用“EP 从 DP 域中切出”的口径，在这个口径下，DP 是配置里的数据并行度，EDP = DP / EP，EDP 才是一套完整专家模型的副本数，一个EDP是一个独立的实例。跨实例之间激活不会相互计算和通信。

也就是说，本案例的训练，一个step下有2个EDP在各跑各的。



激活在 Layer 输出通常可以抽象成形状为 [B, S, H] 的 hidden state，其存储大小由形状和数据类型决定，与张量中的数值大小无关。因此，在模型结构不变的重复层之间，边界激活的逻辑大小通常相同。

讨论一个 Layer 时，还要区分“同名 Layer 集合”和“Layer 实例”。例如模型有 46 个 Layer，每个 EDP 副本都有自己的 Layer0 和 PP Stage0。所有 EDP 中的 Layer0 合在一起，是同名 Layer 集合；某一个 EDP 中的 Layer0，才是一个具体的 Layer 实例。

在实际执行中，每个 EDP 是一条相对独立的完整流水线。不同 EDP 不需要等到彼此完成 Layer0，才继续执行 Layer1；PP Stage 之间的激活传递也只沿同一个 EDP 内部的流水线发生。不同 EDP 之间不交换前向激活，它们的主要同步发生在反向阶段的梯度归约，并且必须在对应的权重更新前完成。实现上梯度归约可以与反向计算重叠，不必理解为等所有反向计算完全结束后只做一次通信。

一个 EDP 内部包含 EP 个专家并行位置。对于普通的 Attention、Norm 等部分，每个数据流主要由对应的 TP ranks 协同计算；进入 MoE 模块后，token 会在同一个 EDP 内的 EP ranks 之间执行 dispatch，专家计算完成后再 combine 回原来的数据流。因此，EP 改变的是 MoE 层内部 token 的临时分布，不应把 Layer 输出长期画成彼此独立的 EP 激活分片。

PP 负责把不同 Layer 放到不同 Stage，并在 Stage 边界传递激活，不切分单个 Layer 的激活张量。DP 表达不同的数据流，EDP 表达完整专家模型的副本；它们都不是把同一份激活切成几块。TP 会影响 Layer 内部张量和计算的分布，但具体哪些激活被切分、哪些在通信后恢复完整，要以算子的 TP 布局为准，不能简单理解为所有激活都被 TP 均匀切开。

讨论权重时，TP 通常切分 Linear 等大权重，但 Norm、Router 等小权重可能在 TP 组内复制。EP 是把不同专家分配给不同 EP ranks，每个专家的权重仍是完整专家权重，而不是由 EP 再切成多片。不同 EDP 上对应的权重是逻辑相同、物理独立的副本，通过梯度同步保持数值一致。在常规均衡配置下，同类 rank 的权重存储量通常接近。

因此，DP × Layer 画布应先表达 EDP 的独立性：外层按 EDP 分成多条完整流水线，每条流水线内部再展示 PP Stage、Layer、EP 和 TP ranks。选择某个 Layer 时，应明确区分“某个 EDP 中的 Layer 实例”和“所有 EDP 中的同名 Layer 集合”；默认查看实例层，只有在做跨副本比较时才选择同名 Layer 集合。





Master、m、v 是优化器状态维度，他们的shape、元素数量和 dtype 都相同，因此容量相同，但保存的内容和作用不同。
m：决定更新方向
v：调节每个位置的更新幅度
Master：接收并保存最终更新结果

## “8-内存”页：峰值与 GAP 应该怎么看

页面要回答的不是“哪个数最大”，而是两个问题：

1. **容量风险**：哪个 Rank 最接近 HBM 上限，峰值发生在什么阶段，还剩多少安全余量？
2. **来源归因**：峰值里有多少是真实业务内存，有多少是延迟释放、池内空闲或通信/runtime？

### 一、四层内存是一份包含账，不是四份内存

同一 Rank、同一时刻、同一组件口径下：

- `A(t)`：算子分配（Operator Allocated），仍被算子逻辑使用的真实业务内存。
- `H(t)`：算子持有（Operator Activated）。
- `R(t)`：算子保留（Operator Reserved）。
- `P(t)`：进程保留（APP Reserved），最接近整卡容量压力。

相邻层差值为：

- `D(t) = H(t) - A(t)`：逻辑已释放，但仍被 Stream / Event 持有的延迟释放量。
- `I(t) = R(t) - H(t)`：已经回到算子内存池、当前空闲的缓存量。
- `O(t) = P(t) - R(t)`：通信、runtime、图执行器等进程级占用。

因此：

```text
P(t) = A(t) + D(t) + I(t) + O(t)
```

四张总量图负责显示水位，三个差值负责解释水位来自哪里。不能用不同时间发生的 `max H - max A` 代替 `max(H-A)`；采样来源、设备、进程和时刻未对齐时也不能直接做差。

### 二、算子分配高不等于坏，算子保留也不能替代它

`A` 高表示真实业务工作集大，可能来自必要权重，也可能来自可重计算激活、热点专家、异常 shape 或过大 workspace。它没有天然的“越大越坏”或“越大越好”，要结合以下条件判断：

- `P` 是否接近 HBM 上限；
- 是否明显偏离同 PP / TP / EP 角色 Rank；
- 增量来自哪类张量、Layer 或算子；
- 是否持续存在，以及是否可以降低。

如果只能选一张图看 OOM 风险，应看 `P`；如果要看真实业务需求，应看 `A`；如果要解释 `P` 为什么比 `A` 大，应看 `D / I / O`。

不能用 `R` 热力替代 `A`：两个 Rank 即使都是 `R = 50 GB`，也可能分别是 `A/D/I = 46/2/2 GB` 和 `18/4/28 GB`，前者是真实工作集，后者主要是池内空闲，优化方向完全不同。反过来，若各 Rank 都预留 50 GB，某个 Rank 的 `A` 从 25 GB 升到 45 GB，只有 `A` 能暴露业务热点。

### 三、内存峰值分析：先找风险，再在同一时刻拆账

对每个 Rank 先找：

```text
tP = argmax P(t)
安全余量 = HBM - P(tP)
```

然后只在同一个 `tP` 分解：

```text
P(tP) = A(tP) + D(tP) + I(tP) + O(tP)
```

页面的主结论应类似：

> R23 在前向 43% 达到 61.2 / 64 GB，余量 2.8 GB；其中业务工作集 41.0 GB、延迟释放 11.2 GB、池内空闲 5.0 GB、通信/runtime 4.0 GB。

`max A(t)` 可以作为“最大真实工作集”的二级入口，但不能单凭它判坏。峰值分析还应显示：峰值阶段、持续时间、同角色中位数/P95、相对偏离和 Top 张量/算子/组件。

### 四、GAP 分析：同时看量、占比、持续时间和后果

| GAP | 主要问题 | 下钻证据 |
|---|---|---|
| `D = H-A` | 跨流释放滞后、慢 kernel、事件等待 | 最后访问 Stream / kernel / Event |
| `I = R-H` | 内存池缓存多或复用效率低 | block、segment、复用率、失败申请 |
| `O = P-R` | 算子账外的进程级占用 | HCCL、runtime、图执行器、PID |

GAP 的优先级不能只按比例排，应综合：

- 峰值绝对量（GB）；
- 同一时刻占 `R` 或 `P` 的比例；
- 高位持续时间或 `∫ GAP(t)dt`（byte-time）；
- 是否与 `P` 高水位重叠；
- 是否挡住后续复用、触发 retry、清池或 OOM。

例如 90% 但只有 0.2 GB、持续极短的 GAP，通常不应排在 12 GB、持续 30% Step 且与容量高水位重叠的问题之前。

`I` 大不等于碎片。只有总空闲量足够，但最大连续块小于失败申请，并伴随 inactive split / non-releasable block、分配重试、清池或 OOM，才有较强的碎片证据。缺少 block/segment 数据时只能称为“池内空闲偏高”。

### 五、Rank 热力图和下钻顺序

1. 先固定同一 step、时刻、设备和采样口径。
2. 按相同 PP Stage、TP、EP 位置比较副本，不把结构性台阶当异常。
3. 峰值页先看 `P / HBM` 和安全余量，再看同一时刻的 `A/D/I/O` 构成。
4. GAP 页按“绝对 GB + 持续时间 + 与 P 高位重叠”排序，占比只作辅助。
5. 选中 Rank 后保持它为主语，联动到峰值时刻和对应的算子、Stream、内存块或组件。

热力颜色应使用固定量程：容量类统一以 HBM 为上限，GAP 类使用固定 GB 区间。不要每帧按最小值/最大值重新拉伸，否则很小的差异也会被渲染成强烈异常，不同时刻的颜色也无法比较。

### 六、数据边界

当前页面使用确定性合成数据，只用于解释分析方法，不能据此输出生产结论。生产分析至少需要对齐 `memory_record`、`operator_memory`、step marker、Stream、内存块、组件/PID 和调用栈。

缺少 Operator Activated 或流信息时，只能计算 `Reserved - Allocated` 的合并 GAP；缺少 block/segment 数据时，不能仅凭 GAP 宣称存在碎片。
