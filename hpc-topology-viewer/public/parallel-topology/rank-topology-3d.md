# 模型分片与训练设备映射（3D 拓扑）· Pattern

> 构建产物：`/patterns/rank-topology-3d/pattern.html`（自包含，带 `?v=<短SHA>` 版本戳）
> 源：`public/parallel-topology/demo.html`，默认落在 `view=chain · card=1 · vtab=3d · embed=1`
> 契约：同级 `pattern.json`

## 它回答什么

**五刀切完之后，这一份落到哪张卡上。** 画的是 world 只卡壳排成的三维阵列，每只装它自己那一份：
PP 决定它拿哪几层、TP 决定每个算子的第几片、EP 决定哪几个专家、DP 决定这套安排复制第几遍。
四刀的交集恰好是一张卡——这句话在这一屏是**可以数出来的**，不是口号。

它**不**回答「一张整网是怎么被切开的」——那是 `/patterns/model-netgraph/` 的题面；
也不回答「一步里什么时候搬」——那是「时间·流」那一屏。

## 三种卡片内容

| 内容 | URL | 卡里画什么 |
|---|---|---|
| 模型分片 | 默认 | 层与算子归属：这张卡拿了哪几层、每层哪几块 |
| 层构成 | `fill=comp` | 逐层一排算子方块：体积 ∝ 字节、颜色 = 切它那把刀 |
| 显存占用 | `net=0` | HBM 五档色带：权重 / 梯度 / 优化器态 / 激活 / 碎片，顶出壳外即超容 |

三种内容共用**同一套点选状态**：选中的 rank 是选中态，沿任一把落下的刀与它同组的兄弟 rank 是默认态，
其余 rank 隐去（内容不画、只留一层淡壳撑住阵列骨架）。

## 通信：一次只画一层

配置面板「通信连线」里六选一（URL `cgrain=`）：

- `rank` —— 谁和谁：卡与卡的边，一条边一枚芯片，芯片上写**关键值**（`34MB · 0.23ms`），名称走悬停
- `tensor` —— 搬的是什么：前态→后态的变换徽章；每块顶上一枚记号，实心 = 这一块自己有跨卡的边
- `route` —— token 去哪了：EP 那几条边逐条按 token 数给宽度，数字标在对端卡上（只有 MoE + EP 落刀时可用）
- `time` —— 何时：`TP·每层×2` / `PP·每 μb` / `DP·步末一次` 写在边上
- `cost` —— 代价：`0.31ms` / `气泡 38%`，边宽随耗时
- `intra` —— rank 内：沿这张卡自己的那一叠层（层构成）或五档色带（显存占用）连线，前 / 反 / 更三个记号

**边连的是块，不是卡**：TP 的归约连 `attn.out`（行切算出的是部分和）、EP 的 All-to-All 连 `experts`、
CP 连 `attn.core`、PP 是「本段的 norm×2 → 下一段的 attn.q」。
每层都发生的维（TP/CP/EP）会画出淡淡的**重复痕**；PP（段边界一次）与 DP（步末一次）没有——
有没有重复痕本身就是这两类通信的区别。

## 约束与不适用

- **通信只在选中一张卡之后出现。** 没有主语就没有「它跟谁来往」这个答案，这是刻意的。
- **通信字节按配置真算，耗时仍是示意口径**。字节：TP / PP 是 `mbs×(seq/CP)×hidden×2B`（激活），DP 是 `2×本卡参数量`（梯度 bf16），标签上一律带量词——`64MB ×2/层`（每层进出 TP 区各一次）/ `64MB /μb` / `5.5GB /步`，不写量词的话四条边会被当成同一口径读，实际重复次数差 2–3 个数量级。CP（逐跳一块 KV）与 EP（各边由 top-k 路由当场决定）**不给数**，宁缺毋误。耗时按算子类别估的量级，非实测，只服务「影响」那一档的相对比较，图上一律带 `≈`。读出卡的九格里「载荷」因此仍标「答了一半」——半在字节已经算得出、耗时还没有。
- `world = TP × CP × PP × DP` 必须整除，不合法时舞台封锁并给最近合法值（宁缺毋误）。
- 4000 卡级别不要默认全量绘制：显式 `net=0`（关掉整网）或降低并行度，否则单帧上万个 SVG 图元。
- 不做实测 profiling 的替代品。它是**结构**的读法，时间轴上的真相去「时间·流」。
- **这一屏没有时间轴**。模型分片答的是「谁持有什么、跟谁来往、一次搬多少」，是静态归属；把耗时钉在边上等于把时间轴上的一个**区间**压成一个点，还不说它落在前向、反向还是步末。所以「看哪一层」在 `rank` 这一档只写载荷，耗时留给 `time`（何时）与 `cost`（代价）两档。

## 物理链与载体（第十层）

前九层问的都是逻辑侧（谁 / 什么 / 怎么搬 / 何时 / 代价），第十层第一次把物理侧接进来：**这条边走哪张网**。

卡（rank）同时挂在两套坐标上：

- 并行坐标 `(tp, cp, pp, dp, ep)` —— 它持有模型的哪一份
- 物理坐标 `(超节点, 机柜, node, 槽位)` —— 它插在哪

两套坐标的交叉决定载体：

| 载体 | 何时 | 带宽 |
|---|---|---|
| **UB 平面**（灵衢 UnifiedBus） | 通信域**全在一个超节点内** | 196 GB/s 单向/卡，非阻塞全互联 |
| **RDMA 平面**（RoCE） | 通信域**跨超节点** | 400 Gbps/卡 —— 比 UB 低一个数量级，真正的降速点 |
| 片内 | 不出卡 | — |

尺寸可配（`perNode` / `nodeRack` / `podCards`，缺省 8 / 4 / 384，照 CloudMatrix384 的公开口径：1 node = 8 NPU + 4 CPU + 7 颗板载 UB 交换芯片；48 node = 1 超节点 = 384 卡，摊在 16 个机柜）。把 `podCards` 调小就能看出哪几条边会掉到 RoCE 上。

> **⚠ 一条口径假设**：超节点内一律按 UB 同一档算，**不区分板内 / 板间 / 机架间**。公开资料的说法是「单板内、单板间、机架间 NPU 全互联」，读起来是同一档；板间与机架间到底有没有降速，待灵衢团队确认。真有差异时改的只是 `fabricOf` 的判定与那张带宽表，图与读数的结构一个字不用动。
>
> 直接的推论：**node 边界在超节点内不是降速点**，AllToAll 在超节点内不因跨 node 而变慢；换挡点是超节点边界。照直觉画成「node 内快、node 间慢」会画反。

两处把这一层画出来：

- **物理平铺**（`?phys=1`）—— 卡按物理坐标摆开，**机柜**是地面上的浅色底带（标 `机柜 N · node a–b`），**超节点**围成一只青色的盒子（标 `超节点 N · M 卡 · UB 边界`）。跨超节点的通信边会明明白白地穿出盒子。
- **读出卡的第十格**（`网`）—— 九层可观测性后面多一格「载体」，按**选中的那张卡**算：这一维的这一组卡在不在同一个超节点里。没选中卡就如实写「没有主语就没有答案」，不猜。

两者合看的最短路径：`?phys=1&cgrain=fabric&sel=23`，再把 `podCards` 调小，就能看出哪几条边从 UB 掉到 RoCE。

### 三个机位各画各的

物理链在三个机位里的画法不同，因为三张图的排法不同——照搬会画错：

| 机位 | 画法 | 为什么 |
|---|---|---|
| **3D / 物理平铺** | 机柜是地面底带、超节点围成青色盒子 | 卡按物理坐标摆，物理相邻＝图上相邻，围框是对的 |
| **正视** | 逐格换框色（同超节点=青 / 跨=橙），号进悬停 | 卡按并行坐标排，物理相邻的卡未必挨着——围框会框住一片不连续的格子 |
| **侧视** | 卡架上的格子换色 | 同上；而且一格只有几像素，写不下「超节点 3」 |

### 代价：传输时间下界

「影响」那一档不再用示意 ms，改成 **载荷 ÷ 带宽**：

- TP `64MB ÷ 196GB/s` → `≥0.34ms`
- DP `5.5GB ÷ 196GB/s` → `≥30ms`
- 跨超节点时带宽掉到 400 Gbps（÷4），同样的字节要久四倍——边会自己粗出来

写「≥」是因为它只算了「搬这么多字节至少要多久」：没算拓扑跳数、没算集合通信算法的系数（环形 AllReduce 要搬 2(N−1)/N 份）、没算争用与协议开销。算不出字节的两维（CP / EP）退回示意 ms 并写「≈」。
