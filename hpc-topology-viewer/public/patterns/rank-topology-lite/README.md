# 模型分片与训练设备映射 · 简洁版 · Pattern

> 构建产物：`/patterns/rank-topology-lite/pattern.html`
> 两个本体：[`/rubik-pattern.html`](../../rubik-pattern.html)（逻辑魔方）+
> [`/patterns/rank-topology-3d/`](../rank-topology-3d/pattern.html)（并行拓扑矩阵）——
> 都是同源 iframe 嵌入，不是拷贝
> 契约：同级 `pattern.json`

## 它是什么

`/patterns/rank-topology-3d/` 的**简洁版**——但这一版的「简洁」不是靠改矩阵本身、也不是靠加一层
弱化渲染凑出来的：未点开任何一张卡时，铺满整个视口的是**逻辑魔方**（`/rubik-pattern.html`，
WebGL 实例化网格）——它本来就是素块、没有文字标签、没有显示密度问题、也没有性能问题，这正是
「点开之前」想要的默认视图，不必在 SVG 矩阵里再拼一套。

默认预置是 **dense64**（`tp4·pp4·dp4·ep1`，world=64）——并行拓扑矩阵本体自己现成的稠密配置。
默认预置先后改过两次：pangu（4000 卡演示规格）→ moe718b128k（`tp8·cp16·pp16·dp4·ep4`，
world=8192，pangu_sophon_pytorch 项目里体量最大的一档真实 MoE，718B 总参/39B 激活）→ dense64。
换到 moe718b128k 之后反馈「这个的rank数量太多了……回退一步回到之前只用64个rank的时候，也就是
并行拓扑本身的pattern的配置」+「等到我们的形式确定之后再扩大rank的数量」——8192 张卡（尤其宇宙
视图一屏撑开的密度）已经压过"先把交互形式定下来"这个当下的目的，退回到 world=64；更大规模
不是删掉，`?preset=pangu`/`moe718b128k`/`incident2048` 仍旧直接可用，等形式定了再考虑扩大默认
规模。`world ≤ 64` 这条规则本身触发的是下面「规模小的时候……」那条早退分支：默认打开现在直接
铺满矩阵本体原页，不铺逻辑魔方——逻辑魔方与三档取景要 `?preset=pangu`/`moe718b128k`/
`incident2048` 才会用上。moe718b128k 是第一个 `CP>1`（=16）的预置——逻辑魔方与矩阵本体的坐标
换算原来只处理 tp/pp/dp 三维（CP 恒为 1 时省了也一样），补上了 cp 那一项，见下面「两套 rank
编号」。

点开一张方块之后，**留在逻辑魔方自己身上**——它自带的选中态渲染（这张卡的四维身份、结构、
"卡内魔方"局部聚焦）已经是干净的效果，不必换到矩阵那一屏再画一遍。宿主在角落浮出一句"↓ 单卡
下钻"邀请，点了才真正换到**并行拓扑矩阵本体**（`/patterns/rank-topology-3d/pattern.html`），
带上那张卡的 `?sel=&solo=1`——这时才是矩阵的强项：真实容量读出、显存构成明细、卡内那一级通信。
见下面「三档取景」。

两个本体都不改功能、不改外观，各自负责它本来就做得最好的那一半：逻辑魔方负责「阵列有多密、排成
什么形状」以及「选中这一张之后它在阵列里的局部上下文」，并行拓扑矩阵只负责「真要下钻时的全部
数字细节」。**拓扑本身就是全屏幕的无限画布**——不是另包一层镜头、把矩阵缩成中间的一张卡片；
两个 iframe 都铺满整个视口，边到边，不加框、不缩小。

**规模小的时候，无限画布本身就是多余的一层**——`world`（`tp×pp×dp`）≤ 64 时，这一份直接铺满
并行拓扑矩阵本体的原页，不铺逻辑魔方、不裁剪它的任何交互，跟直接打开 `/patterns/rank-topology-3d/`
逐字节相同。64 张卡的 SVG 阵列本来就没有密度/性能问题，逻辑魔方"先看形状"的价值这时反而是
多绕一圈——见下面「URL 参数」的 `preset`。

## 三档取景

「无限画布」是三个真实档位，越往里画得越少、看得越细：

1. **集群**——逻辑魔方铺满，没有选中任何卡。
2. **选中**——点一张魔方方块之后，**留在逻辑魔方身上**：它自己的选中态渲染（局部聚焦、四维
   身份）原样接管，这一层不换 iframe、不重画一遍；但 `cc=0`/`cclabels=0` 关掉了它画布里
   "卡内魔方"那份层/算子构成的显示（见下面「URL 参数」外的渲染约定）。宿主右上角这时浮出
   一张详情卡：选中的瞬间先是一句极简的"↓ 单卡下钻"邀请（rank 号 + 坐标 + 层段，来自逻辑
   魔方自己 `onSelect` 报的数，不留空白），紧接着悄悄借矩阵本体一次不铺屏的 `?brief=1&sel=`
   请求把这张卡自己的层区间/显存构成算出来（跟第三档 `ptoRankBrief` 读的是同一份口径），
   回信一到就原地升级成真数据——不用先点"下钻"才看得到层/分片/显存。
3. **单卡下钻**——点那句邀请，才真正换到并行拓扑矩阵本体，带 `fastcard=1&solo=1`：连兄弟卡
   也隐去，看的是这一张卡内部的填充版——真实容量读出、显存构成明细（保留矩阵原本的彩色：
   权重/梯度/优化器态/专家/激活各自的颜色在说"这一块字节是什么"，不是装饰；这一档只服务
   一张卡，不会跟别的卡的颜色打架，彩色比黑白更好读）、卡内那一级通信。宿主右上角这时才
   浮出真数据卡，内容是矩阵上报的、已经算好的摘要（坐标、层段、容量告警、显存构成）——这
   一层自己不重算、不编数字，读出面板与浮卡永远是同一套数。

退档不靠宿主自己另起一颗按钮：点空白就是每一档自带的手势，**一次退一档**，不直接甩回最外层。
第 3→2 档不换 iframe，只让矩阵切自己的 `soloCard`（矩阵自己的"点空白"手势 + 一句 `pto:tier`
指令）；第 2→1 档是逻辑魔方自己的"点空白取消选中"，才真的把矩阵藏起来，回到逻辑魔方——它本来
就还停在原地，不用重新加载。档位写在面包屑里（逻辑魔方顶栏的模型名 + `rank N` 后缀、矩阵自己
的画布名字），不必再摆一颗按钮复述"你在哪/怎么回去"。tier2 完全不涉及 iframe 切换，天然没有
闪烁，这也是"切换要丝滑"这条要求最终落地的方式：不是靠更长的过渡动画补出来的，是靠少切一次
省出来的。

## 宇宙视图（第一档的第二种画法）

`?view=universe`，或点右上角「🌌 宇宙视图」切换钮：第一档换一种画法——不铺逻辑魔方 iframe，
铺一张内联 SVG 径向星图。中心节点是模型本身（名字 + world 卡数），第一圈 hub 是各条 **PP 段**
（沿用这个仓库里"PP流水=段"的既有心智模型，跟逻辑魔方 PP流水形态、并行拓扑矩阵段落条讲的是
同一件事，不是另起一套分类），段内再按 **TP×CP** 分出子组（子 hub，TP=CP=1 时退化成没有子组，
直接进内层——比如 incident2048），子组内是这个 `(pp,tp,cp)` 组合下**全部** `DP` 个 `rep`，一个
不少——`tp·cp·pp·dp` 四个因子相乘正好等于 world，这一屏画的是全部 world 张卡，不是抽样取景。

第一版每段固定抽 9 颗叶子做取景，反馈「这个宇宙视图中间的rank也要按照真实的数量来，现在的数量
是远远不够的，而且只有PP的分类」——现在这版补齐两件事：数量是真的（不抽样）、分类不止 PP 一层
（段内再分 TP×CP 子组）。叶子铺位靠 `layoutWedge()`：把 N 个点摊进一段楔形（角度×半径的二维
网格），不是全挤在一条半径线上——数量一大（比如 pangu 预置一个子组 100 颗）单线摆不下会挤成
一坨看着像一个点，二维摊开才看得出"这里真的有一百个"。数量超过 12 颗时不逐个画到 hub 的连线
（密的时候连线糊成一团黑，比不画还难读，靠点的聚簇位置就够看出归属）。

交互复用的是既有三档机制，不重新发明一套：

- 点一颗**叶子** = 进第二档，直接算好 `sel` 调 `showTier2` / `rubikSelToMatrixSel`——跟逻辑魔方
  `postMessage` 报上来的选中走的是**同一条代码路径**，落的是同一张 `briefCard`；两种视图只是
  "从哪里触发选中"不同，第二/三档的下钻与渲染一个字不重复实现。
- 点一颗 **hub 或子 hub**（段/子组本身）= 只聚焦，把其余段的 hub/子 hub/射线/叶子调暗，不下钻
  ——它们都不对应唯一 rank。
- 点空白 = 退回总览，跟逻辑魔方"点空白取消选中"是同一个心智动作，只是发起点换了。

`world ≤ 64` 的预置（`dense64`，也是当前默认）没有这一档可切——那条早退分支直接铺满矩阵原页，
压根没有逻辑魔方/宇宙视图可选，切换钮不出现。moe718b128k（world=8192）子组多达 128 个/段，实测
渲染要 20 秒级——按"等到形式确定之后再扩大rank的数量"这条节奏，这档暂不追求流畅，不做专门优化。

这一版**没有**做参考图里那种"AI 分析/问答"输入框：那是接了真实 agent 的产品功能，这里接不出
来，摆一个点了没反应的假输入框比不摆更误导人，所以没做。

## 集群聚合角标

三档取景里，第一/二档故意不摆容量/显存数字（见上，矩阵没打开，编不出来）——但这不等于集群
这一层对容量情况完全没有交代。左上角常驻一颗小角标，一开场就借矩阵 iframe 跑一次
`?embed=1&preset=..&brief=1`：demo.html 收到 `brief=1` 会跳过 `urlLoad()` 之后那一整套
`render()`，只算一遍全网容量聚合（`ptoClusterBrief()`——逐卡复用 `capVerdict`，跟悬停提示、
第三档详情卡同一处口径，不另起一份容易对不上的近似算法）就地 `postMessage` 报数，不建
4000 张卡的 SVG、不占那几秒渲染开销。角标文案是"⚠ 超出容量 · N/4000 卡"这类聚合统计，不展开
到每张卡；点它直接下钻到 ratio 最高的那张卡（第三档），跟第二档那句"↓ 单卡下钻"邀请殊途
同归。这次借用与第三档真正下钻时矩阵 iframe 的导航互不冲突——只是同一个 `<iframe>` 多一次
不可见的加载，第三档进来时 `src` 照常换成真正的详情页。

## 结构

- **逻辑魔方（第一/二档，只在 `world > 64` 的预置才铺，比如 `?preset=pangu`）**：`<iframe>` 指向
  `../../rubik-pattern.html?theme=dark&tp=8&pp=5&dp=100&ep=2&color=neutral&groupgap=3`（示例用的是
  pangu 预置的取值，与矩阵本体的 `world=4000` 口径一致；当前默认预置 dense64 的 `world=64 ≤ 64`
  走的是下面「规模小的时候」那条早退分支，压根不铺这个 iframe），铺满整个视口。`color=neutral` 与
  `groupgap=3` 是这个简洁版才传的两个参数：前者默认素色（先看阵列形状，不看负载热力），后者
  拉开 tp/pp/dp/ep 各组之间的缝，让分组更明显——独立打开 `/rubik-pattern.html` 默认值不变。
  它自己的旋转/缩放镜头、形态切换（标准/DP/EP/TP/PP/物理）、着色镜头、时间轴、选中态渲染——
  全部照常可用，这一层不裁剪它的任何功能，选中之后也不会被换掉。
- **并行拓扑矩阵（第三档，只在点了"下钻"之后才加载）**：把逻辑魔方报的 `(tp, pp, rep)` 坐标
  换算成矩阵本体自己的 `rank` 编号（见下方「两套 rank 编号」），矩阵 iframe
  （`../rank-topology-3d/pattern.html?embed=1&theme=dark&preset=pangu&fastcard=1&solo=1&sel=...`）
  这时才第一次加载。矩阵自己的读出面板、六档通信、拖动缩放镜头、显存构成的原色——全部照常
  可用；`fastcard=1` 做几件收敛：选中之后不画坐标轴刻度/EP 组框、选中即刻飞焦到那张卡、取消
  选中飞回默认机位。`solo=1` 连兄弟卡也隐去，只看这一张卡内部——矩阵现在只在第三档才被打开，
  打开就直接是这一档。不传 `mono`：第一/二档的素色是给"阵列有多密"这类形状问题用的，第三档
  问的是"这一张卡里装了什么"，颜色这时是信息不是装饰，所以保留原色。`rank-topology-3d` 直接
  打开不传这两个参数，外观和交互一个字节不变。
- **退档不靠按钮**：点空白就是每一档自带的手势——逻辑魔方点空白取消选中（第 2→1 档），矩阵点
  空白退出 solo（第 3→2 档，一句 `pto:tier` 消息，不重新加载 iframe）。档位读法交给面包屑：
  逻辑魔方顶栏的模型名 + `rank N` 后缀、矩阵自己的画布名字（`stitle=`），不再另摆一颗
  「← 返回…」按钮复述"你在哪/怎么回去"。
- **完整独立页链接**：屏幕下方正中一个极小的角标，点开是矩阵本体的原页
  `/patterns/rank-topology-3d/`——放在下边正中是因为两个本体各自的标题/设置按钮都占了上半区，
  这是唯一稳定空着的一角。

## 两套 rank 编号：为什么点选要换算，不能直接传数字

逻辑魔方与并行拓扑矩阵各自独立实现了一遍「rank ↔ (tp, cp, pp, dp) 坐标」的换算，内部打包顺序不一样：

| | 打包公式 |
|---|---|
| 逻辑魔方 `pattern.js` | `rank = ((rep × PP + pp) × CP + cp) × TP + tp` |
| 并行拓扑 `demo.html` | `rank = ((pp × DP + dp) × CP + cp) × TP + tp` |

两边都用 `tp` 当最内层（`% TP` 同一个数），但 `pp` 与 `dp`/`rep` 的打包顺序不同——同一个数字在
两个系统里指的不是同一张卡，必须按坐标四元组换算，不能把 `rank` 数字直接抄过去。
`pattern.js` 里的 `rubikSelToMatrixSel()` 做的正是这件事：拿逻辑魔方 `onSelect` 回调给出的
`{tp, cp, pp, rep}`，按矩阵本体自己的公式重新打包成它的 `sel`。`cp` 字段是这次新加的——
逻辑魔方的 `onSelect`/`onDrill` payload 原来没给这个数（CP=1 的预置里恒为 0，没人问过也不影响
结果），moe718b128k（CP=16）第一次真的用上它，`vendor/rubik-cube/pattern.js` 补了这个字段
（纯新增，旧消费者不读它不受影响）。

**已验证**（CP=1，pangu 预置）：逻辑魔方 rank 830（`tp=6, pp=3, rep=20`）换算得到矩阵 rank
2566；用 `?sel=2566` 直接打开矩阵本体，它读出的坐标正是 `tp6 · cp0 · dp20 · pp3`，与逻辑魔方报
的坐标逐位一致。

**已验证**（CP=16，moe718b128k 预置）：逻辑魔方选中 `tp=3, cp=9, pp=8, rep=2` 换算得到矩阵
rank 4427；矩阵本体读出的坐标正是 `tp3 · cp9 · dp2 · pp8`，与逻辑魔方报的坐标逐位一致——cp
那一项没有跟着 CP>1 一起失灵。

## URL 参数

| 参数 | 取值 | 作用 |
|---|---|---|
| `sel` | 并行拓扑矩阵自己的 rank 编号，如 `2566` | 打开时直接进入第三档，显示这张卡的填充版详情——用的是矩阵本体自己的编号，不是逻辑魔方的编号（深链场景不经过逻辑魔方，没有换算的必要，也没法换回第二档——退回来会直接落到集群那一档） |
| `preset` | `dense64`（默认，`tp4·pp4·dp4·ep1`，world=64）\| `pangu`（`tp8·pp5·dp100·ep2`，world=4000）\| `moe718b128k`（`tp8·cp16·pp16·dp4·ep4`，world=8192）\| `incident2048`（`tp1·pp4·dp512·ep64`，world=2048） | 选 `world ≤ 64` 的预置时，直接跳过逻辑魔方与三档取景，铺满矩阵本体的原页——验证的正是"规模小时无限画布本身是多余一层"这条规则确实会触发，不是摆着不用的死分支。真实故障复盘面板任何预置都会显示，见下一节 |
| `view` | `universe` | 第一档换成内联 SVG 径向星图（中心=模型 · 一圈=PP 段 · 段内再分 TP×CP 子组 · 叶子=真实的全部 rep，不抽样），见上面"宇宙视图"一节。也可以不带这个参数，直接点右上角「🌌 宇宙视图」切换钮，随时来回切、不重新加载页面。`world ≤ 64` 的预置（含当前默认 dense64）没有这一档可切 |

## 真实故障复盘面板

反馈「类似这种放过来，这里的数据作为卡片放过来」（附了 `/incident-canvas/` 的告警时间线与"训推大盘·关键少数"两张截图）——这份数据逐字抄自那份页面的 `GROUPS`/`TRAIN_METRICS`/`BOARD`（那份本身照抄 compute-graph-viewer 的 `INCIDENT_GROUPS`，数值一个没改）。视口底部常驻一条面板（**任何预置打开都有**）：两条问题线（Router 溢出与通信死锁 / 显存峰值与碎片 OOM）共 11 个事件的时间线，圆点按严重度着色；点一个事件，下面十格"关键少数"指标卡（`lm loss`/`grad_norm`/`loss_scale`/`throughput`/`MFU`……）按这次事件的原文更新，没采到的格子一律显示"—"。

**默认展开时间线，但只展开有数据的部分**：反馈「默认展开数据只展开有的数据」——时间线随时都是真数据（11 个真实事件），默认就露出来，不必先点一下折叠钮才看得见；但十格指标卡在没选中具体事件之前一格数字都没有，展开了也只是十个"—"占位，不算"有数据"，所以这块卡片网格由 `renderIncidentPanel()` 按有没有选中事件（`incidentSel`）决定画不画，跟"面板整体收起/展开"（`is-collapsed`，读者手动点折叠钮才会加上）是两件独立的事——选中一个事件之后卡片网格才出现。

原来这块面板只在 `?preset=incident2048` 才渲染，默认屏幕只留一条链接，点了才整页跳到那份拓扑——反馈「不希望问题定位的那一块儿和本身的拓扑是分离的，现在必须要点击左上角的告警才能进入有数据的界面，我希望这个界面直接显示在最外层的拓扑上」，渲染逻辑挪到了 `world ≤ 64` 分流之前，任何预置打开都会看到这块面板，不用先跳转页面。

这是**另一起独立的 2048 卡训练**的真实事故，tp/pp/dp/ep 取值（`tp1·pp4·dp512·ep64`）是从事故原文自己的拓扑常量（`pp=4·edp=8·ep=64`）反推的——world=pp×edp×ep=2048，本页公式 world=tp×cp×pp×dp，故 dp=edp×ep=512、ep=64（`domOf`=dp/ep=8 自动等于 edp）。取这组数字是唯一能让 demo.html 自己的 `rankOf`/`epOf` 公式算出跟事故原文一致 rank 号的取法：`rank 1559 → pp3·ep23`、`rank 1553 → pp3·ep17`，与原文"PP3/EP23""PP3/EP17"逐位对上。`layers=48`：事故原文真实 46 层按 `[12,12,10,12]` 不均匀分段，本页要求 `layers%pp===0`，48 是能让病灶 Layer 38 仍落在 PP3 段的最近合法值；`hidden`/`heads`/`ffn`/`vocab`/`seq`/`mbs`/`ga` 这几项事故原文没给模型架构细节，沿用同一模型家族"盘古ProMoE·4000卡"那档，不是从事故分析抄来的。

右上角悬浮的显存构成卡渲染的是本页自己按这些借来的架构字段估出的假设值（比如 167GB），跟面板里引用的事故原文数字（比如"64.0/64 GB"）不是同一套口径——两者一起出现时，面板自己的页脚会重复这句提醒，别把"工具按猜的架构估出的数"和"事故报告里的真实数"混着读。

**下钻按钮按当前预置换说法**：有具体 rank 的事件（`p1-log`/`p1-a2a`/`p2-oom`）带一颗按钮——当前预置就是 `incident2048` 时显示"下钻 rank N →"，直接跳到矩阵第三档看这张卡的真实坐标读出；不是 `incident2048` 时（比如默认 `dense64`）显示"查看 rank N 所在的真实拓扑 →"，点了整页跳转到 `?preset=incident2048&sel=N`。这个区分是必要的：事件里的 rank 号（1559/1553 这些）是 incident2048 那份 2048 卡拓扑自己坐标系里的真实 rank，当前预置不是 incident2048 时这个数字在当前这张拓扑上并不存在（默认 dense64 只有 64 张卡）——不能假装能在当前页面内下钻到同一张卡，那是编数据，所以改成整页跳转到这个数字真正有意义的那张拓扑。

## 它不回答什么

- **完整的并行度组合切换**——两个本体各自的 preset / 自定义 tp·cp·pp·dp·ep、ZeRO 档位、物理平铺
  都还在，只是这一份把默认值定死在 dense64 预置。想换配置，直接在对应的本体内部操作，或用
  `?preset=` 换成这一份桥接过的其他档位。
- **逻辑魔方与矩阵本体之外的第三套渲染**——这一层只做「选谁、换算成谁的编号、切哪个 iframe 在
  上层」，不重新画卡、不重新算内存/容量，那些都是两个本体各自的职责。
